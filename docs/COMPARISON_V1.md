# AO-X02-4 saved evidence comparison

Source implementation for [Issue #34](https://github.com/bobrs/Application-Observatory/issues/34), under delegated supervisor authority, from accepted `main` at `d786e4507fbae777f48cbd5c65751cb62e34f04f`. This is a read-only return journey using [X02-3 safe evidence reads](EVIDENCE_V1.md), not collection, workload repair, verification or an operational gate. Source-worker checks, supervisor review, separately attributed evaluation and deployment remain separate.

Let `B = /applications/:slug/targets/:targetId`. A focused target page now offers **Compare this snapshot with current evidence**. Evidence v1 packets add `links.compare` (HTML) and `links.comparison` (JSON) using that packet's snapshot as the baseline; the existing packet schema, field meanings and projection version are unchanged.

| GET/HEAD route | Behavior |
| --- | --- |
| `B/compare?<baseline descriptor>` | Saved/current columns, added record counts, changed fact labels, native identities/times, separate receipt/uncertainty/continuation, safe snapshot/record/page links and a copyable comparison link. |
| `B/comparison.json?<baseline descriptor>` | Compact `observatory-comparison-v1` JSON with the same baseline/current selection. |

A complete existing descriptor is required: `backend`, `instance`, `eventsThrough`, `directivesThrough`, `evaluatedAt`, `config`, `projection`. The strict X02-3 parser rejects absent/partial, repeated, extra, malformed and oversized queries; `before` is not accepted on comparisons. Existing slug/ID/Host boundaries apply. Unsupported projection, changed configuration/backend/incarnation, missing retained ledger or required record explicitly makes the comparison unavailable. No current scope replacement is presented as confirmation of an old operation. Descriptors remain client-requested historical views, not authenticated capture attestations.

One outer SQLite deferred read transaction contains the baseline packet projection, current projection, compact required record reads and both exact-scope counts. Nested reader transactions are savepoints on that connection. The baseline keeps its original event/directive upper bounds and evaluation time. The current projection captures its own bounds and evaluation time in the same database read view. Neither projection uses operational `state()` or performs a target request. All safe record/page links carry the complete descriptor for their own column. Following a column's pinned target/JSON links preserves that column; refreshing the comparison or downloading comparison JSON keeps the baseline but reevaluates current persisted evidence.

The JSON shape contains:

- `comparisonSchema`, current renderer `projectionSource`, exact shared `scope`, normalized `configuration` and structured uncollected `attribution`.
- `baseline` and `current`, each with `snapshot`, compact `facts`, exact retained `totals` and safe `links`. Facts retain latest/last-known native outcome/version/artifact/boot and collection/record times, desired identity/time, separate receipt outcome and operation/record times, continuation decision and its original named witness IDs/outcomes/refs. Unknown nulls and withheld/uncollected attribution remain distinct. No packet preview arrays or full ledgers are copied.
- `baselineReevaluation`, which evaluates the frozen baseline latest/last-known observation at the current evaluation time, separately from its original `freshAtEvaluation`. Missing observations use null; a present unknown observation is not a fresh successful read.
- `changes`: exact `addedEvents` and `addedDirectives`, `noNewRecords`, `evidenceChanged`, `projectionChanged`, `freshnessChanged`, `selectedFreshnessChanged`, `baselineFreshnessChanged`, `freshnessOnly` and bounded `changedFacts` labels. Labels distinguish persisted observation/directive/receipt/continuation changes from freshness and dependent read projections. Descriptor-specific URL differences are not evidence changes.
- `links`, `gaps` and `completeness`, including response budgets and the absence of full ledgers.

Added counts cover only the exact current backend/application/target/incarnation and include eventless directives. Other targets and historical scopes do not increment them. An arriving record can have an older collection time and leave the selected latest/last-known fact unchanged. A later periodic read can change record/time without changing version, artifact or boot. No-new-records is explicit; stale aging can change receipt/read-back and continuation projections with no new evidence. Saved-observation aging is visible even when a new current observation is fresh. Evaluation is never substituted for collection or recording time.

Matching read-back and witnessed continuation preserve an unknown or missing receipt. Completed receipts can remain unconfirmed; freshness loss can make a previously qualifying read historical. Original continuation witnesses remain named even when later matching reads support the current continuation projection. Health, independent Test, HTTP status/latency, verified collector identity, author, trigger and deployer are not inferred. Planned comparisons contain configuration, descriptors and safe snapshot links, with null runtime facts/counts and explicit metadata-only copy, including when the logical destination retains an earlier runtime archive.

Both formats reuse the known configured credential guard before JSON serialization or HTML rendering, including URI-encoded forms, and check the finished HTML. A match fails closed with generic 409; native identity is never rewritten. Unrestricted source/detail/actor/rationale remain withheld. Unknown arbitrary secrets in otherwise trusted native fields remain outside this narrow credential-detection guarantee. No external source text becomes a URL, no collector bearer is supplied, and access/operational authority is not granted by a link. Original local archives remain separately accessible outside pinned context.

JSON is capped at 128 KiB; HTML at 256 KiB. Compact required summaries remain available even if the underlying individual packet uses its bounded manifest. An over-budget comparison returns explicit 413 and directs the reader to individual safe snapshots, without silently trimming a required fact. Native links/downloads/disclosures work without browser JavaScript; the two columns stack on narrow viewports. Existing managed forms and all ingestion, collector protocol, gates, schema, configuration and dependencies are unchanged.

Developer checks use Node 24.22.1: `npm ci`, `npm run verify`. Nine added comparison groups cover actual competing SQLite insertion between projections, added observations/receipts/eventless directives, frozen and reevaluated freshness, later matching reads and original unknown witnesses, older backfill versus selected change, no-data/planned/scope isolation, query/config replacement, no-fetch/GET/HEAD/nonaction/count invariants, credential guard, and maximum-ID manifest JSON/HTML budgets. Supervisor source-independent review, browser/large-history measurements and any deployment are reported separately; these developer checks are not independent organizational Test acceptance.
