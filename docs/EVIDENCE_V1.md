# AO-X02-3 safe evidence reads

Implemented for [Issue #32](https://github.com/bobrs/Application-Observatory/issues/32) under delegated supervisor authority. The [accepted design](AO_X02_DESIGN.md) remains the product contract. This document describes source behavior, not deployment or independent Test acceptance.

With external runtime configuration enabled, let `B = /applications/:slug/targets/:targetId`. External target names on Environments and application detail open `B`. Normal/local reference modes retain their existing routes and meanings. Managed focused pages link to the existing application control section; observe-only and planned pages have no operational controls. Planned packets contain configuration and archive links, with `facts: null` and empty runtime previews, even when that logical target retains earlier managed evidence.

| GET/HEAD route | Result |
| --- | --- |
| `B` | Focused HTML, current or pinned with the descriptor below. Native current/download/pinned links and a selectable snapshot-link field. |
| `B/evidence.json` | Current safe packet with generated pinned link. |
| `B/evidence.json?<descriptor>` | Pinned safe packet. |
| `B/records/events/:eventId` | Single safe logical-archive record, explicitly historical; a full descriptor instead selects exact pinned scope/bounds. |
| `B/records/directives/:directiveId` | Equivalent safe directive read. |
| `B/records/events?<descriptor>&before=…` | Safe exact-scope event pages, 20/page. Without descriptor, begins a new current snapshot. |
| `B/records/directives?<descriptor>&before=…` | Safe exact-scope directive pages, 10/page, including eventless directives. |
| `B/history` and `B/directives` | Existing original local HTML archives with unrestricted text, across retained backend/incarnation scopes, 20/page. |

The descriptor consists of exactly `backend`, `instance`, `eventsThrough`, `directivesThrough`, `evaluatedAt`, `config` and `projection`. Projection is `observatory-projection-v1`; `evaluatedAt` is canonical millisecond UTC ISO text, and `config` is a 64-character SHA-256 fingerprint. Extra, duplicate, partial, malformed or over-2048-character queries are rejected. Cutoffs are safe nonnegative integers tied to retained logical-target ledger rows (or zero); page cursors satisfy `1 <= before <= corresponding cutoff + 1`. Both descriptor bounds are carried by safe record, correlation, witness and paging links. Safe read links bound application slugs to 160 characters; an oversized context fails explicitly. The router accepts parameters up to 160 characters so the existing 120-character protocol IDs remain reachable. Target membership is checked before lookup; IDs cannot select another logical application/target.

A single SQLite deferred read transaction captures the two logical-target ledger upper bounds, freezes evaluation time, and reads all exact `(backend, application, target, incarnation)` summaries, witnesses, previews and counts. Every pinned subquery applies its ledger bound. This does not call the operational `ExternalRuntime.state()` or change its gates. The projection retains its existing chronology and reconciliation criteria, distinguishes latest unknown from historical last-known success, and separates freshness from contradiction and receipt outcome. Missing/unknown receipt outcomes remain unknown after matching read-back or continuation.

Configuration is an explicit normalized declaration allowlist: backend/schema, application ID/slug/name/purpose and the entire selected target ID/name/application/stage/incarnation/mode/limitations/artifact pairs. Artifact pairs use canonical version ordering in both fingerprint and exported configuration. Paths, credentials and configuration locations are excluded. Changed configuration/scope, unsupported projection or missing retained cutoffs/witnesses return **Pinned snapshot unavailable**, normally 409; removed configuration and missing/out-of-bound records return 404. No current replacement is silently substituted. Client-selected time/cursors request a historical view and are not an authenticated capture attestation. Links depend on retained append-only evidence and current compatible configuration; save the downloaded packet for an enduring copy. No durable snapshot storage or migration is added.

The JSON schema is `observatory-evidence-v1`. Its top-level sections are `projectionSource`, `scope`, `configuration`, `snapshot`, `facts`, `attribution`, `records`, `directives`, `preview`, `links`, `gaps` and `completeness`. `facts` uses safe record references plus independent projection flags; native IDs/version/artifact/boot, original nulls, outcomes, evidence/operation/record times, directive correlation and original reconciliation witnesses are preserved. Required latest/last-known/receipt/reconciliation/witness records are selected separately from the recent preview and deduplicated by kind/ID. The current renderer checkout SHA and dirty state identify the code rendering this response when Git metadata is available; otherwise they are explicitly unavailable. This producer metadata is not workload provenance or the frozen original snapshot producer. A new renderer must support the declared projection semantics or reject the old projection version.

All unrestricted source/detail/actor/rationale values are withheld, including in single records and safe pages. An attribution slot carries `value`, `availability`, `provenance`, `recordRef`; missing roles are independently uncollected/unknown and unsafe declarations are withheld. No alias is fabricated from a source string. HTTP status/duration, verified collector identity, author, trigger and deployer are uncollected; health and independent Test remain not evaluated. There is no raw object/payload dump, free-text source auto-link, CSRF field, bearer credential, private path/endpoint, command, provider payload or log export.

Default packets include at most 20 recent events and 10 recent directives, plus required witnesses. Previews have exact retained counts and safe page links. Above 128 KiB uncompressed, an explicit bounded manifest retains all required fact references and safe page links while omitting inline record bodies; it reports the limitation. Focused HTML is limited to 256 KiB and three consequential preview records. Existing raw local archives are separately labeled: their initial links freeze the corresponding ledger only; following legacy cross-ledger navigation leaves the pinned snapshot. Use safe record/page links for pinned investigation. The legacy directive `lookup` now also respects its archive's own directive cutoff.

All new routes retain no-store, nosniff, restrictive CSP, Host/loopback boundaries and JSON MIME/validated server filenames. They require the reader's existing application access, do not expose a collector bearer and grant no operational authority. GET/HEAD handlers only select persisted evidence: no collection request, target probe, operation, replay or ledger write. The safe packet is a handoff to separately authorized tools, not a repair controller.

Developer verification is `npm ci` then `npm run verify` on Node 24.22.1. New adversarial fixtures cover a real competing SQLite writer inserting an event and eventless directive between cutoff reads, both fences and lookup escapes, scope/config replacement, unsafe text omission, malformed/bounded queries, preserved unknowns/original witnesses, read-only counts/no fetch, complete page traversal, and forced budget overflow. A 20-target/10,001-observation mixed-incarnation fixture reports one cold and ten warm samples, byte counts, median/p95 and runtime/machine context. These are developer measurements, not production SLAs or independent Test. The existing browser navigation harness now follows the focused target route; supervisor review, separate evaluation/captures and deployment are recorded separately.
